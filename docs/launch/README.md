# 文澄首发材料

准备日期：2026-11-08。适用版本：`0.1.0-rc.1` 及当前仓库的安装适配。

这些文件用于准备发布，尚未向 V2EX 或 Hacker News 提交内容。

现有演示已包含中英文各三张实际界面截图及一个 GIF 轮播，见[图文演示](../DEMO.md)。它展示标注、建议对照和应用修订；不是连续录屏，也未把轮播时长当作模型响应速度。60–90 秒连续录屏仍是后续录制计划。

安装入口为[中文 README](../../README.md#通过-skillssh-安装)和[English README](../../README.en.md#install-through-skillssh)。[安装验收报告](INSTALLATION-VALIDATION.md)记录实际完成的范围；以本地源码通过的结果不能替代公共仓库安装验收。

V2EX 和 HN 的现行规则均要求避免发布 AI 生成的社区内容，HN 还明确涵盖 AI 修改后的内容。因此，两份社区准备卡不是可直接粘贴的帖子；作者需要根据亲自使用和开发的经历自行撰写，不能仅修改几个词后转贴通用介绍稿。规则来源见各准备卡。

## 发布前执行清单

- [ ] 推送后打开公开仓库首页，确认中英文截图、GIF、安装入口及 Release 链接可访问。
- [ ] 用全新目录完成 README 中的安装步骤；核对 skill 和应用均可运行，不依赖开发目录或旧的 `WENCHENG_ROOT`。
- [ ] 核对对外安装命令与实际发布的 commit 一致；本地通过尚未推送的命令不能作为公共安装入口。
- [ ] 从初次启动走完一次“导入 → 标注 → 建议 → 应用为修订 → 导出”，记录发生的安装或使用问题。
- [ ] 检查演示只含公开合成样例；视频中不出现账号、密钥、私人路径或第三方论文正文。
- [ ] 作者自行完成两个社区的标题和正文，复核当日社区规则、链接和下载文件名。
- [ ] 首先选择自己能及时回答问题的发布时间；按渠道分别发布，不自动同步社区帖子或评论。
- [ ] 将社区帖 URL、发布日期和主要反馈记入维护记录；公开问题可引导到 GitHub Issues。

社区帖应链接到[仓库首页](https://github.com/yc13665193882-source/wencheng)，让演示、安装方法和最新说明集中在同一入口。首轮下载为 [v0.1.0-rc.1](https://github.com/yc13665193882-source/wencheng/releases/tag/v0.1.0-rc.1)。仓库公开和 Release 可用不代表 skill 已进入第三方目录。

## 回答用户问题时可核对的事实

以下是事实资料，不是可批量粘贴到社区的回复。

| 用户可能问什么 | 已知事实与可引用位置 |
| --- | --- |
| 必须安装什么？ | Python 3.11+。通过 skills CLI 安装 skill 还需要 Node.js 22.20+；随后执行 skill 的 `setup` 下载固定运行包、核对 SHA256 并安装 Python 依赖。预构建运行 ZIP 本身不要求 Node.js。模型调用还需要用户自己的可用提供方。安装命令以当前 [README](../../README.md) 为准。 |
| 必须订阅某个模型吗？ | 应用不捆绑模型服务。当前聊天 skill 使用所在对话；侧栏 CLI/API 是独立调用，分别需要安装、登录或 API 配置。 |
| 文档会上传吗？ | 项目文件默认保存在本机。调用模型时，选区、必要上下文与指令会交给所选提供方；不能将它宣传成所有处理均离线。 |
| 会改公式或参考文献吗？ | 当前自动改写主要覆盖正文及表格单元格。公式、域、脚注尾注、参考文献和已有修订等结构受保护。参考文献识别含启发式规则，异常格式需人工核对。 |
| 接受建议后还有修订吗？ | 有。在文澄中应用建议会写成 Word 插入／删除修订；导出后可继续在 Word 中接受或拒绝。它不等于在 Word 中执行“接受所有修订”。 |
| 浏览器和 Word 分页相同吗？ | 浏览器版式是辅助预览。Word 校样可查看用户从 Word 导出的 PDF；后续改稿会提示旧校样过期。 |
| 哪些环境真正验收过？ | Windows 浏览器、真实 Codex CLI 中英文流程、Microsoft Word 2021。CI 结果与范围看 [Actions](https://github.com/yc13665193882-source/wencheng/actions)；Claude Code 和兼容 API 的协议模拟不等于真实账号验收。详见[验收概览](../VALIDATION.md)。 |
| 是否适用于所有 DOCX？ | 不能作通用无损保证。已有复杂合成样例和中英文长文档记录，编辑范围与未覆盖项在验收概览中列明。 |
| 反馈什么最有帮助？ | 系统与 Python 版本、所用安装命令、失败步骤和可公开的最小样例。涉及私人文档时，可先用合成文本复现问题。 |

## 观察首轮效果

每周记录仓库访问、Release 下载、安装问题、完成一次使用的反馈和新增 Star。下载或克隆数不代表实际使用人数。GitHub Traffic 的访问与克隆视图覆盖最近 14 天，适合按周保存汇总，见 [GitHub 文档](https://docs.github.com/en/repositories/viewing-activity-and-data-for-your-repository/viewing-traffic-to-a-repository)。

首轮重点是找到阻碍安装和首次完成任务的问题。不要用集中点赞、重复安装或重复发帖来制造热度。
